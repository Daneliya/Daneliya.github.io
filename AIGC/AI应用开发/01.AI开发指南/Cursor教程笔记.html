1. 概述 ​

1.1 Cursor 是什么？ ​

Cursor 是一款基于 VS Code 构建的 AI 驱动代码编辑器，集成了 GPT-4、Claude 3.5 等大型语言模型，目标是在不改变开发者习惯的前提下，用 AI 提升编码效率和质量。

1.2 与 VS Code 的关系 ​

维度说明
底层基于 VS Code 开源代码构建
插件完全兼容 VS Code 扩展生态
操作界面、快捷键、设置体系与 VS Code 一致
差异原生集成 AI Chat / Composer / Tab 补全 / @ 上下文引用
学习成本VS Code 用户几乎零成本上手

1.3 核心 AI 功能一览 ​

功能说明快捷键
Tab 补全（Copilot++）根据上下文智能预测并补全代码编码时自动触发
Cmd+K / Ctrl+K选中代码，用自然语言指令修改Ctrl+K
Chat交互式 AI 对话，解释/调试/学习Ctrl+L
Composer多文件代码生成，按需求文档构建Ctrl+I
@ 符号引用文件/文件夹/代码库/Git/网络等作为上下文对话中输入 @

1.4 同类产品对比 ​

产品开发商特点
CursorCursor Inc.VS Code 基础 + 原生 AI
GitHub CopilotGitHub/Microsoft插件形式，需 VS Code
Qoder阿里巴巴国内 VS Code 分支
Trae字节跳动国内 VS Code 分支

2. 安装与初始配置 ​

2.1 系统要求 ​

操作系统版本要求架构
WindowsWindows 10 1903+x64 / ARM64
macOS10.15 Catalina+Intel / Apple Silicon
LinuxUbuntu 18.04+ / Debian 10+ / RHEL 8+x64 / ARM64

硬件最低要求：4GB RAM（推荐 8GB+）、2GB 磁盘、支持 SSE2 处理器、稳定网络。

2.2 下载 ​

官网：https://www.cursor.com/downloads，自动匹配操作系统。

2.3 Windows 安装 ​

  1. 官网下载 .exe → 双击运行
  2. 选择安装路径（建议默认）
  3. 点击 Install → 等待完成 → Finish 启动

2.4 macOS 安装 ​

  1. 官网下载 .dmg → 双击打开
  2. 拖动 Cursor 图标到 Applications 文件夹
  3. 从 Applications 中双击启动

2.5 Linux 安装 ​

Debian/Ubuntu：

bash
sudo dpkg -i cursor_<version>_amd64.deb
sudo apt-get install -f
1
2

Fedora/RHEL：

bash
sudo rpm -ivh cursor_<version>_x86_64.rpm
1

2.6 首次启动配置 ​

  1. 选择界面语言（建议中文）
  2. 可选：从本机 VS Code 导入扩展
  3. 注册账号（支持 GitHub 授权登录）
  4. 勾选默认选项 → Continue 完成

3. 界面与基础操作 ​

与 VS Code 完全一致：

  • 活动栏（左侧）— 文件、搜索、Git、扩展、运行
  • 编辑区（中央）— 标签页式代码编辑
  • 面板区（底部）— 终端、问题、输出、调试控制台
  • 状态栏（底部）— 编码、行号、语言模式等

核心操作：

操作方式
打开文件夹/项目Ctrl+K Ctrl+O 或菜单 → File → Open Folder
新建文件Ctrl+N
命令面板Ctrl+Shift+P
扩展商店Ctrl+Shift+X
切换终端Ctrl+`

4. 中文设置（全方位） ​

4.1 界面汉化 ​

方法一：扩展商店安装（推荐）

  1. Ctrl+Shift+X 打开扩展商店
  2. 搜索 "Chinese"
  3. 安装 Chinese (Simplified) Language Pack for Visual Studio Code（发布者：Microsoft）
  4. 右下角弹窗提示重启 → 确认

方法二：命令面板手动切换

  1. Ctrl+Shift+P → 输入 "Configure Display Language"
  2. 选择 "zh-cn" → 重启

Cursor 特有功能（如 Composer、Agent 模式）部分界面可能保持英文，正常现象。

4.2 AI 中文回复 ​

配置方式作用范围优先级推荐场景
Rules for AI（全局）所有项目低个人默认设置
.cursorrules单个项目中项目级统一规范
.cursor/rules/*.mdc单项目（可按文件过滤）高大型团队精细化管理

全局配置（最快）：

File → Preferences → Cursor Settings → General → Rules for AI，输入：

Always respond in Chinese (Simplified).
代码注释使用中文。
技术术语保留英文原文，并在首次出现时用括号标注中文翻译。

5. AI 模型配置 ​

5.1 内置模型 ​

Cursor 默认预设了 GPT-4、GPT-3.5 等模型，Pro 用户可直接使用。

5.2 添加自定义模型（如 DeepSeek） ​

  1. 右上角齿轮 → Models
  2. 底部点击 Add Model
  3. 输入模型名称（如 deepseek-v3、deepseek-r1）
  4. 配置 API Key 和请求地址：
    • API Key 获取：model 官方平台（如 platform.deepseek.com）
    • 请求地址：https://api.deepseek.com/chat/completions
  5. 点击 Verify 验证
  6. 去掉其他模型勾选，只保留需要使用的模型
  7. 在聊天窗口下拉菜单中选择对应模型即可

5.3 常见模型 API 地址参考 ​

模型API 地址
OpenAI (GPT-4)https://api.openai.com/v1/chat/completions
DeepSeekhttps://api.deepseek.com/chat/completions
通义千问https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
Moonshothttps://api.moonshot.cn/v1/chat/completions

6. Chat 与 Composer ​

6.1 定位区别 ​

维度ChatComposer
用途交互式问答、代码解释、调试多文件代码生成、需求驱动构建
范围单文件/单问题跨文件/整个项目
场景解释代码、修 bug、添加注释建新功能、重构、按需求文档生成项目
快捷键Ctrl+LCtrl+I

6.2 Chat 使用 ​

  1. Ctrl+L 打开聊天面板
  2. 输入自然语言指令（如"给这段代码添加中文注释"）
  3. AI 返回修改建议
  4. 点击 Apply 应用到文件

Chat 会记住对话上下文，支持逐步深入提问。

6.3 Composer 使用 ​

  1. 创建需求文档描述要实现的功能
  2. Ctrl+I 打开 Composer
  3. 让 AI 根据需求文档生成代码
  4. AI 分析需求后自动创建/修改多个文件
  5. 通过额外指令迭代优化

6.4 推荐工作流 ​

需求分析 → 写需求文档 → Composer 生成代码 → Chat 解释/优化 → 完成

7. @ 符号：上下文引用利器 ​

在 Chat / Composer / Cmd+K 中输入 @，触发上下文引用菜单。

7.1 全部指令 ​

指令功能典型场景
@Files引用整个文件让 AI 基于某个现有文件修改
@Folders引用整个文件夹批量分析多个文件
@Code引用特定代码片段针对某几行代码提问
@Codebase搜索整个代码库全局查找相关代码
@Git引用 Git 提交/差异分析最近改动、排查故障
@Web搜索网络信息获取最新文档或资料
@Docs引用预设文档按官方文档生成代码
@Definitions引用附近所有定义理解当前作用域上下文
@Chat引用之前的对话在聊天中引用历史消息

7.2 组合用法 ​

可以同时使用多个 @ 指令：

@Files src/models/user.js @Docs https://jwt.io/introduction
生成用户登录功能
1
2

7.3 实用案例 ​

场景指令示例
代码生成生成用户登录 @Files src/models/user.js @Docs JWT
错误排查解释报错原因 @Code 12-25行 @Git HEAD~1
跨文件重构改为函数式组件 @Folders src/components @Codebase
学习概念解释这段代码在哪里被调用 @Codebase

7.4 高级配置 ​

  • .cursorignore：类似 .gitignore，排除敏感文件不被索引
  • 自定义文档：Settings → Features → Docs 添加自定义文档链接，增强 @Docs 覆盖

9. 网络优化（国内用户） ​

问题说明
AI 服务延迟Cursor AI 推理服务部署在海外，Chat/Composer/Cmd+K 可能较慢
编辑器本身不受影响，本地编辑、文件操作正常
替代方案可使用 API 中转服务优化连接；网络不佳时优先用 Tab 补全（对网络要求低）
