三、核心问题详细解答 ​

3.1 Prefix LM vs Causal LM ​

来源：快手一面面试题

核心区别：对上下文信息的利用方式不同。

维度Causal LM（因果语言模型）Prefix LM（前缀语言模型）
建模逻辑单向建模，每个token仅依赖左侧已出现的token分段建模：前缀段双向依赖 + 预测段单向自回归
注意力机制下三角注意力掩码，完全屏蔽右侧信息混合注意力掩码：前缀段内双向，预测段内单向
典型模型GPT系列、LLaMAT5、UL2(Prefix LM模式)、PEGASUS
适用场景纯生成任务：对话、续写、代码生成条件生成任务：摘要、翻译、问答
优点工程实现简单，生成速度快兼顾理解与生成，灵活性更强
缺点上下文理解受限模型结构复杂，推理速度稍慢

关键认知：Prefix LM允许上下文样本之间进行全局注意力（双向），在In-Context Learning任务中可能优于Causal LM。

3.2 Flash Attention算法设计原理 ​

来源：wushixiongai.com 架构-注意力优化

问题背景：标准Attention的HBM访问复杂度为 O(N²)，GPU算力被内存带宽瓶颈严重制约。

核心设计：

  1. 分块计算（Tiling）+ Kernel融合

    • 将Q、K、V分割成小块（如64/128）
    • 所有计算在GPU高速片上SRAM中完成（速度约为HBM的100倍）
    • 避免实例化完整的 N×N 注意力矩阵，HBM读写量从 O(N²) 降至 O(N)

  2. Online Softmax（安全融合）

    • 维护当前最大值 mᵢ，处理新块时增量更新
    • 通过缩放因子 e^(m_old - m_new) 调整之前的指数项
    • 增量更新归一化分母，保证数值稳定性

训练 vs 推理价值：

场景核心收益
训练显存从 O(N²)→O(N)，配合重计算策略，支持训练更长序列
推理配合KV Cache减少HBM访问瓶颈，Prefill阶段收益显著

版本演进：v1证明可行性 → v2优化非矩阵乘法 → v3为Hopper架构(H100)优化

3.3 PPO vs DPO vs GRPO 对比 ​

来源：wushixiongai.com 强化学习-算法对比

对比维度PPO（近端策略优化）DPO（直接偏好优化）GRPO（广义无奖励策略优化）
核心模型数量4个(Actor, Critic, RM, Ref)2个(策略模型, 参考模型)2个或1个
是否需要RM是否否
是否需要Critic是否否
核心思想裁剪目标函数限制更新幅度跳过RM，直接用偏好数据优化策略组内相对奖励估计优势
训练稳定性稳定但需精细调参好依赖奖励规则质量
适用场景通用复杂对齐任务快速迭代、简单偏好数学/代码等可验证任务
代表模型ChatGPT(InstructGPT)Llama系列对齐DeepSeek-R1

选型建议：

  • 通用聊天对齐 → PPO或DPO
  • 数学/代码推理 → GRPO
  • 快速原型 → DPO
  • 工业界常用两阶段：DPO快速对齐 + PPO精细调优

3.4 DPO vs PPO 深度对比 ​

来源：wushixiongai.com 强化学习-对齐方法

核心区别：优化范式根本不同

  • PPO：在线强化学习，三模型架构，"探索→反馈→更新"循环
  • DPO：离线监督学习，单模型架构，将RL问题转化为分类问题
维度PPODPO
算法原理在线RL，与RM交互优化策略离线分类，直接最大化chosen/rejected似然比
实现复杂度高，需维护多个模型低，几行代码即可实现
训练稳定性差，易出现reward hacking和模式崩溃好，凸优化问题
效果上限高，在线探索能力强中，对分布外数据敏感
数据需求中等（需RM打分）需成对偏好数据

DPO局限：效果依赖BT模型假设，分布外泛化弱，长文本生成信号衰减严重。
PPO不可替代场景：强探索任务（数学推理/代码生成）、长文本生成、多轮交互。

3.5 大模型优化方法全景 ​

来源：wushixiongai.com 基础设施-模型优化

三大阶段优化策略：

训练阶段 ​

优化方向方法效果
并行策略数据并行(DDP/FSDP)、模型并行(Tensor/Pipeline)、ZeRO优化突破单卡显存限制
计算效率混合精度(FP16/BF16，提速2-3倍)、梯度检查点(节省40-60%显存)、Flash Attention(提速2-4倍)显著提升训练速度

推理阶段 ​

优化方向方法效果
内存优化KV Cache + PageAttention + MQA/GQA降低长文本显存占用
计算优化Continuous Batching提升GPU利用率
解码优化投机解码(Speculative Decoding，提速2-3倍)、并行化Top-K/Top-P降低延迟

部署阶段 ​

优化方向方法精度损失
量化INT8(SmoothQuant)<1%
量化INT4(GPTQ/AWQ)2-5%
蒸馏模型蒸馏可控
服务层模型切分部署(PP+TP)、请求调度(优先级队列/抢占式)-

系统性优化思维：「全栈分析 → 定位瓶颈 → 针对性优化」

  • 瓶颈在通信与计算？→ 优化并行策略
  • 瓶颈是内存带宽？→ 量化 + KV Cache优化
  • 瓶颈是请求波动？→ 弹性扩缩容 + Continuous Batching

3.7 ReAct框架 ​

来源：字节一面面试题

ReAct = Reasoning + Acting，三个核心组件循环：

Thought → Action → Observation → Thought → Action → Observation → ...
1
组件含义作用
Thought（思考）LLM分析当前状态，决定下一步做什么推理与规划
Action（行动）执行具体操作（调用工具/API/搜索）与环境交互
Observation（观察）获取行动结果作为反馈更新状态，指导下一步

与传统LLM的区别：传统LLM一次性生成答案；ReAct Agent通过"思考→行动→观察"循环，逐步推理并利用外部工具完成任务，更可靠、可解释。

3.7 LLM vs Agent ​

来源：阿里一面面试题

维度LLMAgent
核心能力文本生成自主决策+执行
记忆仅上下文窗口短期+长期记忆系统
工具使用无可调用API/数据库/搜索等外部工具
规划无可分解任务，制定多步计划
交互被动响应主动执行、多轮交互

Agent = LLM + 规划(Planning) + 记忆(Memory) + 工具使用(Tool Use) + 行动(Action)

3.8 Agent工具调用 vs 普通函数调用 ​

来源：美团二面面试题

维度普通函数调用Agent工具调用
调用方式代码显式调用LLM自主决策何时调用
参数生成程序员硬编码LLM根据上下文动态生成
结果处理固定逻辑LLM解析结果并决定下一步
灵活性固定流程动态适应不同场景

核心差异：Agent的工具调用是语义驱动而非代码驱动，由LLM理解用户意图后自主决定调用哪个工具、传什么参数、如何利用结果。

3.9 RAG幻觉定位与解决 ​

来源：淘天三面面试题

系统定位方法：

  1. 检索问题：检索到的文档是否真正相关？→ 检查chunk策略、Embedding模型、检索算法
  2. Prompt问题：上下文是否被有效利用？→ 检查System Prompt是否要求基于上下文回答
  3. 生成模型问题：模型是否倾向于忽略上下文？→ 检查模型能力、温度设置

解决策略：

  • 检索层面：优化chunk分隔、混合检索(向量+关键词)、Rerank重排序
  • Prompt层面：明确指令("仅基于提供的上下文回答")、结构化提示、引用要求
  • 模型层面：选择更强指令遵循能力的模型

3.10 RAG Rerank（重排序） ​

来源：京东面试官连环问

为什么需要Rerank：初步向量检索可能召回20条，其中15条不相关 → 需要二次精排

Rerank模型选择：不直接用GPT-4的原因

  • 成本：GPT-4调用费用高，不适合高频打分
  • 延迟：GPT-4推理慢，影响整体响应时间
  • 专用性：Cross-Encoder重排序模型(BGE-Reranker、Cohere Rerank)专为此任务优化

流程：检索(Top-K) → Rerank精排 → 取Top-N送入LLM生成

3.11 RAG性能优化 ​

来源：京东二面面试题（首字响应5秒）

环节优化策略
检索加速向量索引优化(HNSW参数调优)、结果缓存、并行检索
Rerank加速使用轻量Rerank模型、减少Rerank候选数
生成加速流式输出(streaming)、投机解码、量化推理
架构优化预取(prefetch)、异步流水线

3.12 PDF/复杂文档解析 ​

来源：阿里二面、字节二面面试题

难点：双栏排版、表格结构、图片内容、语义完整性破坏

解析策略：

  1. 版面分析：先用版面检测模型识别文字/表格/图片区域
  2. 分模块处理：
    • 纯文本 → 标准段落分块
    • 表格 → 专用OCR + 结构化提取（保留行列关系）
    • 图片 → 多模态模型理解或OCR提取文字
  3. 语义分块：按语义边界分块，而非固定长度切分
  4. 元数据保留：保留页码、章节、标题层级等结构信息

3.13 归一化层详解 ​

来源：wushixiongai.com 架构-归一化

为何Transformer用LayerNorm而非BatchNorm：

维度BatchNormLayerNorm
归一化维度跨batch，同一特征维度跨特征，同一样本内
batch_size依赖强依赖，小batch不稳定不依赖
序列长度适应差好，天然适配变长序列
训练/推理一致性需维护running mean/var天然一致

LayerNorm vs RMSNorm：

维度LayerNormRMSNorm
计算方式减均值+除标准差仅除均方根(RMS)
计算量较高减少约1/3（去掉均值计算）
训练速度较慢快7-15%
主流选择BERT/GPT-2LLaMA系列/PaLM

LLaMA选择RMSNorm的原因：计算效率更高，在训练稳定性上表现不差，已成为新一代模型标配。

3.14 位置编码 ​

来源：wushixiongai.com 架构-位置编码

作用：Transformer的自注意力机制本身是置换不变的（permutation-invariant），位置编码为模型注入序列顺序信息，使其能够区分"我爱你"和"你爱我"。

主要类型：

  • 绝对位置编码：正弦/余弦(Sinusoidal)、可学习(Learned)
  • 相对位置编码：注意力计算中考虑token间相对距离
  • 旋转位置编码(RoPE)：通过旋转矩阵编码相对位置，LLaMA/GPT-NeoX采用

3.15 PyTorch动态计算图 ​

来源：wushixiongai.com 训练-框架原理

核心机制：

  • Define-by-Run：每次前向传播构建新计算图，图结构随输入动态变化
  • 自动微分：反向传播时沿计算图自动计算梯度（链式法则）
  • 优势：灵活支持变长输入、条件分支、循环等动态结构

3.16 Agent长期记忆 ​

来源：面试官追问

存储方案：

  • 短期记忆：对话历史（上下文窗口内）
  • 长期记忆：
    • 向量数据库存储(如Milvus/Pinecone) → 语义检索
    • 知识图谱 → 结构化关系
    • 用户画像/偏好存储 → 个性化

检索策略：

  • 相似度检索（向量）
  • 时间衰减（越近越重要）
  • 混合检索（关键词+语义）

3.17 LLM面临的主要挑战 ​

来源：wushixiongai.com 综合-挑战

挑战说明
计算资源消耗训练/推理成本极高，千亿参数模型需要大量GPU
推理延迟自回归生成速度慢，影响实时应用
幻觉问题生成看似合理但事实错误的内容
上下文长度限制长文本处理能力受限（虽有改进但仍存在）
可控性与安全性难以完全控制输出，存在安全风险
评估困难开放式生成质量难以自动化评估
